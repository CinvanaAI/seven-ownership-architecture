# The Seven Ownership Architecture: mechanism

[The seven ownerships](../THE-7-LAWS-OF-THE-7-OWNERSHIPS.md) define the method. [Pressure signals](../PRESSURE-SIGNALS.md) and [state categories](../STATE-CATEGORIES.md) distinguish evidence from assumptions. The larger Skeleton case study remains available in SYSTEM/, OWNERS/ and CASE-STUDY/, alongside reusable TEMPLATES/. The new small example demonstrates how to use the records without first learning that larger system.

## Limits that matter

This is a proposed architecture method, not a theorem that seven is the optimal number of components. Record absent responsibilities as absent. The CSV example is a designed teaching scenario, not a claim that an external application was audited or refactored.

## Demonstration contract

Input: A small CSV importer with responsibilities mixed into its interface.

Expected observation: A worked ownership map and separate identity, current-state and future-direction records.

The bundled example uses synthetic material. Its observed output establishes that bounded path, not every possible integration.
